# scene 数据块契约

## 1. 位置与格式

图层稿 HTML 里 `<script id="scene" type="application/json">` 的那段 JSON 就是**唯一事实来源**：
版面、底图、所有图层（文字与线段）全在里面。人改、AI 改、脚本改，都改它。

```html
<script id="scene" type="application/json">
/*<<<SCENE>>>*/
{ …… }
/*<<<END SCENE>>>*/
</script>
```

- 两个标记是脚本定位用的锚点，**缺一不可**，也不许出现在别处（注释里也不行）
- `layers` 里**每个元素独占一行**，方便做单行 diff 和最小改动
- 改完用 `node scripts/build.cjs set --html 稿.html --scene scene.json` 写回，已内联的底图不会重复编码
- 只写 `point` / `para` / `line` 三种。早先版本有个 `kind:"row"` 价格行，引擎载入时会把它自动拆成
  点文本+线段+点文本（老交付件不用手工迁移），但**新稿子不要再写 `row`**
- **设计坐标仍是"像素"，pt 只活在页面板子上**：属性面板把字号与描边宽度显示/输入成 pt，落回数据块前按
  `px = pt × design.w/(page.wmm/25.4)/72` 换算（见 §7）。手工或让 AI 改数据块时，`size`/`width`/`ow` 一律写设计像素，
  没有 `pt` 这种单位；稿子没有 `page` 时面板就退回显示像素

## 2. 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | 字符串 | 导出文件名前缀，同时是页面标题 |
| `design` | `{w,h}` | **设计坐标尺寸 = 底板图像素尺寸**。`build` 自动填，别手改 |
| `board` | data URI | 底板图（无文字）。由 `build --board` 内联，scene.json 里不要写。页面顶部「换底板」会就地改写它（图片重新内联、坐标一律不动，Ctrl+Z 可换回来），改完必须「下载 HTML」才落地 |
| `ref` | data URI | 参考图（有文字，已缩到 `--maxref` 宽）。供页面内「叠影/差值」比对 |
| `paper` | 颜色 | 舞台底色，底板透明处露出来 |
| `yink` | 布尔 | 全局「墨迹坐标」开关，见第 4 节。**从参考图量位置就开它** |
| `page` | `{wmm,hmm}` | 印刷纸张尺寸，PDF 与打印用。`build --dpi` 反推或 `--page 420x297` 指定。属性面板上的 pt 也靠它换算，没有 `page` 时字号/宽度只能按像素显示 |
| `text` | 对象 | 全局默认文字样式：`font/weight/size/lh/ls/color/align/direction`，元素未写的字段继承它 |
| `fonts` | 字符串数组 | 本机家族名。属性面板里「字体」框展开后就是这张表（打字即在这张表上过滤），所以要 `build --fonts auto` 才有内容 |
| `faceWeights` | `{家族:[400,700]}` | 每个家族**真实存在**的字重。渲染时按它做字重降级 |
| `facePs` | `{家族:{400:"MicrosoftYaHei"}}` | 每个家族各字重的 **PostScript 名**（fonts.cjs 读 name 表 nameID 6）。只有这份稿子用到的那几个家族，`build --fonts auto` 填。**只有出 PSD 用得上**：PS 的文字层按 PostScript 名找字体，写家族名会被替换成别的字面 |
| `layers` | 数组 | 所有图层（点文本 / 段落文本 / 线段），顺序即叠放顺序 |
| `cff` | 字符串数组 | `build --fonts auto` 的**轮廓体检结果**：这份稿子里哪些家族是 CFF/可变轮廓。页面点「印刷 PDF」时据此在状态行提醒（这类字体的 PDF 会写成 Type3，AI 里多半转轮廓）；手写 scene.json 不用管它 |

## 3. 元素字段

只有三种 `kind`：**`point` 点文本、`para` 段落文本、`line` 线段**。属性面板按选中的类型只显示对应的那几行，
所以写字段时也别串台 —— 线段不需要 `size/font/text`，文本不需要 `x2/dash`。

| 字段 | 默认 | 用于 | 说明 |
|---|---|---|---|
| `kind` | `point` | 全部 | `point` / `para` / `line` |
| `text` | — | 文本 | 内容。`\n` 是硬换行（点文本里表示多行，段落里表示重新起段） |
| `direction` | `horizontal` | 文本 | `horizontal` 横排 / `vertical` 竖排。竖排逐字向下，换列从右到左；PSD 保留为可编辑的竖排文字层 |
| `x` `y` | — | 全部 | 文本见第 4 节；线段是**起点**坐标 |
| `x2` `y2` | — | 线段 | 终点。水平线可以只写 `x2`（`y2` 默认等于 `y`）；竖线只写 `y2` |
| `len` | — | 线段 | 不写 `x2` 时的替代：从 `x,y` 往右画这么长 |
| `width` | 2 | 线段 | 线宽（设计坐标）。点线的点直径也等于它 |
| `style` | `solid` | 线段 | `solid` 实线 / `dashed` 虚线 / `dotted` 点线 / `dashdot` 点划线 / `longdash` 长虚线 |
| `dash` | 按 `style` | 线段 | 显式「画 空」序列（设计坐标），写了就覆盖预设。`"0.1 15"` = 每 15 像素一个点，`"40 12"` = 40 长划 + 12 空 |
| `w` | 到右边界 | 段落 | 框宽，决定折行（点文本自动量宽，写了也没用）。选中段落时**画布上直接拖框的左右边线**就能改（拖左边线会同时挪 `x`，右边线钉住），面板「框宽」是同一个值 |
| `h` | 自动 | 段落 | 框高，只在 `fit` 判定时起作用。同样可以拖框的上下边线改（拖上边线会同时挪 `y`）；拖过之后 `fit` 会自动从 `grow` 收回 `wrap`（否则框会自己长回去） |
| `size` | `text.size` | 文本 | 字号（设计坐标单位） |
| `lh` | 1 | 文本 | 行距倍数（乘在 `size` 上） |
| `ls` | 0 | 文本 | 字距。DOM 用 `letter-spacing`，画布用 `ctx.letterSpacing`，两边一致 |
| `font` `weight` | `text.*` | 文本 | 家族名与字重，字重会被 `faceWeights` 就近降级 |
| `color` | `text.color` | 全部 | 字色 / 线段颜色 |
| `align` | `text.align` | 文本 | `left`/`center`/`right`，段落另有 `justify` 两端对齐。段落内每行按它对齐；点文本还决定 `x` 的锚点含义 |
| `fi` | 0 | 段落 | **首行缩进**，单位同字号（设计坐标）。只缩每段的第一行（`\n` 之后算新段），其余行顶格 |
| `kin` | `strict` | 段落 | **标点避头尾**：`strict` 严格（禁则标点被上一行拽下来）/ `loose` 宽松（标点允许悬挂在框外）/ `off` 无（按宽度硬断）。`NO_HEAD`（不能行首）与 `NO_TAIL`（不能行末）两张表在引擎里，中英文标点都覆盖 |
| `dy` | 0 | 文本 | 垂直微调。字形与参考图差半格时用这个，别改 `y` |
| `bg` | 无 | 文本 | 文字底色块（色块跟着包围盒走），用于在底板上重新铺一块纯色再写字 |
| `pad` | `[0,0,0,0]` | 文本 | 底色块内边距，CSS 顺序：上 右 下 左 |
| `radius` | 0 | 文本 | 底色块圆角 |
| `fit` | `wrap` | 段落 | 超框：`wrap` 溢出并标 ⚠ / `shrink` 自动缩字号到装得下 / `grow` 框长高 |
| `cap` | 按 `style` | 线段 | 端头 `butt` 平头 / `round` 圆头 / `square` 方头。不写就跟着 `style`（点线默认圆头） |
| `g` | 无 | 全部 | 组号栈（数组，内层在前），如 `[1,2]`＝先成了组 1、整组又进了组 2。同组图层算一个整体：点任意一个整组选中、整组拖动，**对齐与等距分布也按整组移动**（组内相对位置不动）。只是"选择单位"，坐标仍各自独立，排版/导出/打印不受影响。右栏「对齐与分布」里的「组合/拆组/全部拆组」= `Ctrl+G` / `Ctrl+Shift+G` / `Ctrl+Shift+A`；拆组只退最外面那一层（ac 与 bd 各自成组后再合成一组，拆组后 ac 仍是组） |
| `lock` | 1 | 全部 | **锁定标记**（只写 `1`，没有就是不锁）。锁住的层不吃鼠标：单击与框选都跳过它，因此拖动、面板、对齐、删除、属性刷一律碰不到；导出照旧带上它。解锁＝工具条「解锁全部」/ `Shift+L`，或 Alt 单击该层就地解锁。写在图层数据里，所以「下载 HTML」会保存、`Ctrl+Z` 能还原 |
| `name` | 取前 12 字 | 文本 | 属性面板标题，可选 |

### 竖排文字

在文字层写 `"direction":"vertical"`，或在 HTML 属性面板选「文本方向 → 竖排」。`point` 的 `x,y` 是文字包围盒左上角；`align:center/right` 仍将 `x` 当作水平中心/右锚点。一个字占一格，顺序从上到下；原文的 `\n` 开新列，列从右向左排。`para` 的 `x,y` 是框左上角，`h` 限制每列高度并触发换列，`w` 限制总列宽；`fi` 是每段首列的顶部缩进，`align:center/right` 将较短列沿高度居中/靠下。`fit:shrink` 可缩字号装入框，`fit:grow` 则让框随内容扩展。未写 `h` 时只在原文换行处换列。界面、图片、SVG 按这些坐标显示；PSD 文字层写入真正的 `vertical` 方向并保留整段原文以便在 Photoshop 中继续编辑。

```json
{ "kind": "para", "direction": "vertical", "x": 120, "y": 80, "w": 160, "h": 360, "size": 32, "lh": 1.2, "text": "第一列文字从上到下，满高以后向左换列" }
```

## 3b. 轮廓描边（文字专用的一组字段）

线段的描边就是它自己（`color/width/style/dash/cap`）；文字要描边则写下面这组 `o*` 字段。
**面板里它们是同一排控件**，按选中的是文字还是线段落到不同字段，所以不用记两套。

| 字段 | 默认 | 说明 |
|---|---|---|
| `ow` | 无 | **描边宽度（设计坐标），也是开关**：`0` 或不写＝不描边。面板里把宽度改回 0 会顺手清空整组 `o*` 字段 |
| `oc` | 字色 | 描边颜色 |
| `ostyle` | `solid` | 描边线型，取值与线段的 `style` 完全一样（`solid/dashed/dotted/dashdot/longdash`） |
| `odash` | 按 `ostyle` | 显式「画 空」序列，覆盖预设。写法与线段的 `dash` 一致：`"14 8"`＝14 长划加 8 空 |
| `ocap` | 按 `ostyle` | 端头 `butt/round/square` |
| `ojoin` | `miter` | 拐角 `miter` 尖角 / `round` 圆角 / `bevel` 斜角。线段只有两个端点、没有拐角，所以**线段没有这个字段** |
| `omiter` | 5 | 斜接限制，尖角处外伸的倍数上限 |
| `opos` | `outside` | 描边落在笔画的哪一侧：`outside` 外侧（**默认**，字保持原粗细向外扩）/ `center` 居中（压在笔画正中，字会显粗）/ `inside` 内侧（只在笔画内部一圈，字不变大） |

```json
{ "kind": "point", "x": 700, "y": 120, "align": "center", "size": 90, "text": "开业大吉", "ow": 6, "oc": "#c0392b", "opos": "outside" }
```

- 描边走的是**真描边**（DOM 用 SVG `<text stroke>`，导出画布用 `strokeText`），不是 `-webkit-text-stroke`，
  所以虚线节奏、端头形状、内外侧都能控制，屏幕上和成品图里是同一圈线
- `outside` 靠 `paint-order`，`inside` 靠剪切（SVG 用字形 `clipPath`，画布用离屏 `source-atop`）——
  实测内侧描边的墨迹包围盒与纯填充**逐像素同范围**，不会把字撑大
- **只有 `ow>0` 的层才换到描边渲染路径**，没描边的层仍走原来的排版，所以给一份旧稿子加几个描边不会让其它层的版面动一丝
- 描边宽度是设计坐标，导出 4K 时跟着等比放大，印刷不会变细
- 就地改字（双击）时描边层会临时退回普通排版以便编辑，提交后自动恢复描边

## 4. 坐标语义

排版只在**设计坐标**里算一次，屏幕、导出图、PDF 都靠 `transform: scale()` 缩放，所以三者版面绝对等比。

- **段落文本**：`x,y` 是包围盒**左上角**，`w` 决定折行，每行按 `align` 在盒内对齐。
- **点文本**：`y` 仍是包围盒顶边，但 **`x` 是锚点**，由 `align` 解释：
  - `left` → `x` 是左端；`center` → `x` 是这行的**水平中心**；`right` → `x` 是右端。
  - 于是改内容长度时文字围绕锚点生长，不会跑偏 —— 居中排版的标题、菜名一律用 `center`。
- **线段**：`(x,y) → (x2,y2)` 是一条真实的线，DOM 画 `<svg><line stroke-dasharray>`、导出画布走
  `setLineDash`，两边共用同一个 `lineOf()` 算出的数组，所以屏幕上看到什么就导出什么。
  编辑态选中它时两端会出现方块，拖方块单独改一头，拖线上任意处整条平移。
- 基线位置由字体度量算出：`baseline = 行顶 + (行高 − (ascent+descent))/2 + ascent`，
  所以同一份数据在 DOM 和 canvas 上落在同一条基线上。

### 价目表那一行怎么排

「菜名 ……… 价格」**不是一个特殊类型**，就是三层叠在一起，`probe.cjs` 已经拆好：

```json
{ "kind": "point", "x": 124, "y": 216, "size": 55, "text": "肉沫豆腐" }
{ "kind": "line", "x": 390, "y": 256, "x2": 620, "y2": 256, "width": 6, "style": "dotted", "dash": "0.1 15" }
{ "kind": "point", "x": 722, "y": 216, "align": "right", "size": 55, "text": "18" }
```

- 菜名 `align:"left"`、价格 `align:"right"`，价格改成三位数也只往左长，整列仍然齐右
- 点线的 `x/x2` 就是参考图上第一段点到最后一段点的墨迹中心，`dash` 的第二个数是实测点距
- 想让点线跟着菜名长度自动伸缩：把 `x` 往左、`x2` 定死到价格左边即可，点会自己填满

### `yink: true`（从参考图量位置时务必打开）

`yink` 打开后，`x/y` 不再按 CSS 的行盒与笔尖解释，而是按**墨迹**：

- `y` = 墨迹顶（不是行盒顶）。不开的话整份稿子会统一偏下 0.2~0.4 个字号，且**每行都偏一样多**，
  热图上表现为每个字下面一道边
- `x` = 墨迹左沿（不是笔尖）。字体左侧本来就有 ~0.1 个字号的空隙，不补回来整列字统一右移半格
- 线段的坐标本来就是从墨迹量出来的，与 `yink` 无关，开着也不会偏

从参考图上量到的**永远是墨迹**（`probe.cjs` 与 `rows.cjs` 输出的都是墨迹包围盒），所以：量 → 填 → 开 `yink`，不用逐条补 `dy`。
手工排版、想按 CSS 盒子给坐标时，把 `yink` 去掉即可。

## 4b. 各字段从哪来（probe.cjs 的产出对照）

`probe.cjs` 拿参考图与底板做像素差，差出来的就是字和线。它直接吐出下面这些字段，**不要手估**：

| scene 字段 | probe 里对应 | 怎么算的 |
|---|---|---|
| 文本 `x` `y` | 墨迹包围盒左上角 | 积分图 + 递归 XY-cut，按空行/空列切到一块一块 |
| `w`（para） | `x1-x0+1` | 行内列投影的两端 |
| `size` | 中位行墨迹高 ÷ `--emh`（默认 0.92） | 填完字后用 `--fit` 换成按墨迹宽反推，精度从 ±5% 收到 ±1% |
| `lh` | 相邻两行 `y0` 之差 ÷ `size` | 只有多行块才给 |
| `color` | 块内差异最强一档的众数色 | 只取掩码像素，避开抗锯齿中间色 |
| `paper` | 非掩码像素的众数色（按面积投票） | 底板补平处的颜色 |
| `kind` | 细长差异带 → `line`；多行 → `para`；否则 `point` | 细长度（长 ≥6×厚、厚 ≤8px）够就判线段 |
| 线段 `x y x2 y2` | 该带两端墨迹的中心 | 点线取第一个点与最后一个点的中心 |
| 线段 `width` | 带的厚度中位数 | 点线就是点的直径 |
| 线段 `style` `dash` | 沿长度方向的墨迹游程 | 游程短且间距规律 → `dotted`，`dash` 写成 `"0.1 点距"`；有长有短 → `dashed`；一整条 → `solid` |
| `nameW` / `priceW` | 菜名段、价格段墨迹宽 | 仅 stdout/blocks.json，供 `--fit` 用，不写进 scene |

**两个字号估计数**，理解它们的差别才不会反复调：

- 墨迹高 ÷ EMH：填字之前就能算，适合批量给初值；不同字体高低差 5% 上下
- 墨迹宽 ÷ Σ字符 em 宽（`--fit`）：必须先知道内容，全角记 1 em、半角记 0.55 em。这是该字体真正的 em，
  实测和手调基线差 +0.4（p10 −0.1 / p90 +1.1）。**没填字的层和线段层 `--fit` 会跳过**，所以顺序永远是「填字 → fit」。
  一块能拆出好几层，所以 `--fit` 不靠层序对号，靠 `blocks.json` 里的 `fits`（`fits[块序] = [[层序, 墨迹宽, 行数], …]`）

**probe 只能量到底板干净的地方。** 它找的是「两张图不一样」的像素，底板里还残留着文字的区域两张图一样，
就一块也量不出来。所以 probe 报的块数少于参考图实际文字数时，先怀疑底板没擦干净（用 `overlay.ps1` 直接比
参考图和底板就能看出来），而不是去调 `--T`。半拉子底板就先把能量出来的这半边交付，并把限制写明。

## 5. 三种图层判定

按"改长之后希望它怎么变"来定，而不是按有几行：

| 场景 | 选择 | 理由 |
|---|---|---|
| 标题、店名、分类牌、单位、按钮文字 | `point` | 改字要左右对称变宽，绝不能自动折行 |
| 菜名（价目表左端） | `point`，`align:"left"` | 每行独立，改字只影响自己 |
| 价格（价目表右端） | `point`，`align:"right"` | 右端钉死，改成三位数也只往左长，整列自然齐右 |
| 菜名和价格之间的引导点线 | `line`，`style:"dotted"` + `dash:"0.1 点距"` | 它本质是一条线：可调颜色、粗细、点距，不需要专门的"价格行"类型 |
| 分隔线、下划线、边框、色条 | `line`，`style:"solid"` | 同上，`width` 就是线粗 |
| 虚线边框/裁切线 | `line`，`style:"dashed"` 或 `longdash` | 要精确控制划空就写 `dash` |
| 商品描述、地址、条款、简介 | `para` + `w` | 需要在固定栏宽里自动回流 |
| 参考图里明显是手动断行的诗句/slogan | `point` + `\n` | 保留硬换行语义 |
| 一整段且超框风险高 | `para` + `fit:"shrink"` | 装不下时自动缩字号，不会溢出压到别的元素 |

## 6. 字体匹配（只用本机字体）

不下载 webfont。写 `font` 之前先查：

```bash
node scripts/fonts.cjs --filter "关键词"      # 家族名<TAB>可用字重
```

家族名支持中文名与英文名两种写法（`宋体` 与 `SimSun` 都在表里），照抄输出里的名字即可。

**铁律：`weight` 必须落在该家族实际有的字重上。** 单字重家族写 700，浏览器会合成假粗 ——
CJK 大字上表现为笔画错位重影，直接毁掉还原度。`build` 会警告，渲染时也会就近降级，
但**降级后就没有粗黑了**，所以正确做法是换家族：

| 参考图观感 | 首选（有字重梯度） | 系统自带兜底 |
|---|---|---|
| 粗黑标题 | `Source Han Sans CN` 700/900、`Alibaba PuHuiTi` 700/900、`HarmonyOS Sans SC` 700/900 | `Microsoft YaHei` 700、`DengXian` 700 |
| 常规黑正文 | 同上 400/500 | `Microsoft YaHei` 400 |
| 宋体/衬线标题 | `Source Han Serif CN` 500~900 | `SimSun`/`STZhongsong` **只有 400** |
| 楷体 | — | `KaiTi`/`STKaiti` 只有 400，要粗就换 `Source Han Serif CN` |
| 仿宋 | — | `FangSong`/`STFangsong` 只有 400 |
| 隶书/圆体/魏碑 | — | `LiSu`/`YouYuan` 只有 400 |
| 手写/美术字 | `STXingkai`、`STHupo`、`zcoolwenyiti` 等 | 全是单字重，别加粗 |

经验：Windows 自带的中文字体（宋、黑、楷、仿宋、华文中宋、隶书、幼圆、ST\* 系列）**基本都只有 400**；
需要字重层次就靠 `Source Han Sans/Serif CN`、`Alibaba PuHuiTi`、`HarmonyOS Sans SC`、`Microsoft YaHei`、`DengXian`。

## 7. 印刷尺寸换算

`design.w/h` 是像素，`page.wmm/hmm` 是纸张，两者靠 DPI 挂钩：

```
wmm = design.w / dpi * 25.4      hmm = design.h / dpi * 25.4
```

- 常见：A4 300dpi → 3508×2480；A3 300dpi → 4961×3508；420×297mm 展板 150dpi → 2480×1754
- 出图倍率与印刷无关：`--width 4k` 就是 4096px 宽，等比放大 `design.w`
- PDF 走 `@page{size:Wmm Hmm;margin:0}`，是矢量文字，放大到任何打印尺寸都不糊。
  但**能不能改字看轮廓类型**：本机装的静态 TrueType → Chrome 嵌成 `Type0+CIDFontType2+FontFile2`（真活字）；
  CFF/OTF、可变字体、内联 `@font-face` 子集 → 一律 Type3（显示/印刷/搜索正常，AI 里常转轮廓）。`build` 把结论记进顶层 `cff` 字段
- PSD 走 `scripts/psd.cjs`（或页面导出弹窗里的两个 PSD 按钮）。**字号两版都写设计像素数字**：实测 Photoshop
  排文字时不按文档分辨率换算 pt（同一份稿子 13.3pt 在 300dpi 和 72dpi 下占同样多的像素），写换算后的 pt 只会
  让印刷版的字小 `dpi/72` 倍。两版只差**文档分辨率元数据**：`print` 写 `design.w/(page.wmm/25.4)`（PS
  「图像大小」里纸张就是 `page` 的毫米数，印刷商要这个）、`px` 写 72（Illustrator/CorelDRAW 那类真按 dpi
  换算 pt 的软件里字也不会走样）。两版像素、位图、压平预览完全相同；`--width 4k` 时像素数字同比放大。
  稿件没有 `page` 时 print 版退回 72dpi，两版就一模一样了
- PSD 里的**线段默认写成形状层**（PS「直线工具」那种）：`vectorMask` 一条开路径、两个锚点（设计像素，与图层坐标同一套），
  `vectorStroke` 带 `lineWidth`(Pixels)/`lineCapType`/`lineJoinType`/`lineAlignment:'center'`/`lineDashSet`(Pixels，就是 `dash` 数组)/
  描边色放 `content`（**0~255**，和文字 `fillColor` 同一口径）。这套字段是拿桌面真实 PS 稿里的形状层逐项比着写的：
  `strokeEnabled:true`＋`fillEnabled:false`，同时仍给一个 `vectorFill`（PS 自己也这么存，填充关掉时不显示）、
  `nameSource:'shap'`、`vectorOrigination:{keyShapeInvalidated:true}`。同一层里位图缓存照写，所以 PS 不重算时与页面逐像素一致。
  `--lines bitmap`（命令行）或弹窗里取消「线段转形状图层」（页面）就退回只有一层像素
- 分层 SVG 走 `scripts/svg.cjs`（或弹窗里的「SVG（分层·活字）」）：`width/height` 有 `page` 时写毫米、
  `viewBox` 始终是设计像素，`font-size` 就是设计像素 —— SVG 没有"按分辨率换算"这一说，是各家设计软件最稳的落点
- 需要出血：把 `page` 加大出血量，同时把 `design` 与底板按同比例留边（一般让设计方导出带出血的底板）

## 8. 导出契约

页面 URL hash 控制导出模式，无头 Chrome 用：

| hash | 效果 |
|---|---|
| `#export` | 隐藏导航条/属性面板/叠影/差值/网格，只留版面 |
| `#export&text` | 再去掉底板与 `paper`，输出透明背景，只留文字与线段（`export.cjs --layer text`） |
| `#export&board` | 反过来：只留底板，文字与线段全隐藏（`psd.cjs` 取 PSD 的底板层） |
| `#manifest` | 不出图：把每层的**生效样式 + 每行基线**编成 base64 塞进 `<pre id="psd-manifest">`，用 `--dump-dom` 读走，然后**把整页拆掉**只留这一段（`psd.cjs` 的排版来源） |
| `#svg` | 同上套路：`svgDoc()` 生成的整份分层 SVG 源码 base64 塞进 `<pre id="svg-doc">`（外面包 `[[[SVG]]]…[[[/SVG]]]`），页面把自己拆掉只留这一段，`svg.cjs` 用 `--dump-dom` 读走还原 |

`#manifest` 与 `#svg` 都用 `dumpOnly()`：`--dump-dom` 会把整页 HTML 打回来（这份稿子 6MB+，`spawnSync` 默认
1MB 上限会截断），所以先拆页再只留那一小段。

`#manifest` 存在的理由：Node 没有字体度量，`layout()`/`metrics()` 只能在浏览器里算一次。清单里给的是设计坐标，
`psd.cjs` 再按 `--width` 乘倍数。改了 `layout()` 不必动 `psd.cjs`；改了清单字段则要两边一起改（`psdManifest()` ↔ `textLayer()`）。

`scripts/export.cjs` 已经封好这些参数，直接用它：

```bash
node scripts/export.cjs 稿.html --width 4k --format jpg
node scripts/export.cjs 稿.html --width 8k --layer text --format png
node scripts/export.cjs 稿.html --format pdf
```

页面内按钮走 canvas 路径，超过 ~2.8 亿像素会拒绝并提示改用脚本 —— 16K 一律用脚本出。

## 9. 还原度调优

改完一轮就量化一次，别凭眼睛估：

```bash
node scripts/export.cjs 稿.html --width 4032 --format png --out chk     # --width = 参考图原生宽度
powershell -File scripts/overlay.ps1 -Render chk-4032px.png -Ref 参考图.png -DiffOut diff.png
```

| 指标 | 含义 |
|---|---|
| 平均通道差 < 6 且 明显差异像素 < 3% | 高度一致，可交付 |
| 平均通道差 < 15 且 明显差异像素 ≤ 11% | 版面已吻合，剩余差异集中在字形 —— 看热图确认没有成形的字影即可交付 |
| 更高 | 结构性偏差，先查底板残留文字，再查字体/字号/x/y |

**必须同尺寸比。** 渲染图和参考图像素数不一样时，脚本会把参考图重采样，字被抹平后差异反而变大
（同一份稿子：4032px 对 4032px = 11.5 / 7.94%；2048px 对 4032px = 13.9 / 15.53%，看着像退步了）。
所以 `--width` 直接给参考图的原生宽度，别用 2k 缩略图判分。

**参考图是 AI 出的图时，别指望刷到 0。** 字形本身和任何本机字体都不是一族，
实测四款候选（微软雅黑 / 黑体 / HarmonyOS Sans SC / 思源黑体 CN）都落在 8~10% 明显差异像素，
这时**用指标选字体**（谁的差异小用谁），剩下的差异只要热图里不再是成形的字影就可以交付。

**注意**：差异里有一块恒定底色来自参考图与底板的图像差异（AI 出图两次不会完全相同），
所以判"高度一致"要看**热图里文字边缘是否还有成形的字影**。文字处仍有清晰字形轮廓 = 位置/字号/字体没对上；
文字处只剩一片模糊 = 已经对了。

排查顺序：

1. **底板残留文字** → 差值热图里文字区域出现两套错位笔画。这是数据问题，回去要真正的无字底板
2. **整体偏移** → `x`/`y` 统一加减；等比错位说明 `design` 尺寸与参考图不同源
3. **整列统一偏右下 ~0.3 个字号** → 没开 `yink`。量到的都是墨迹，按行盒/笔尖排就会统一偏
4. **单块错位** → 该元素 `dy`（垂直半格）或 `align`（居中没居中）
5. **字宽对不上** → 字体不对（同字号下宽度差 5% 以上就不是同一族）或 `ls` 字距
6. **行高对不上** → `lh`，多行文本先量行间距再反推倍数
7. **粗细不对** → 查 `faceWeights`，换有该字重的家族
8. **引导点线不对** → 它是普通线段：点距看 `dash` 第二个数、点的大小看 `width`、起止看 `x`/`x2`。
   和参考图差一两个点是正常的（点数由墨迹边界倒推）；整条线偏移才是 `x/x2/y` 的问题
