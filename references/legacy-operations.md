# 设计图转可编辑 HTML 图层稿

## 核心思路

AI 出图快但文字必乱码，且图片无法二次编辑。本 skill 把成品图拆成 **底板图（无文字）+ 真实图层**，
输出一个自包含的单文件 HTML：底板当背景，图层按参考图 1:1 绝对定位叠上去，全部存在一个 `scene` JSON 数据块里。
**只有三种图层**，别发明第四种：

| 图层 | 是什么 | 能调什么 |
|---|---|---|
| 点文本 `point` | 一行字：标题、菜名、价格、标签 | 内容、位置、字体字号行距字距颜色、底色块、**轮廓描边**（宽度/颜色/线型/虚线/端头/拐角/斜接/内外侧） |
| 段落文本 `para` | 要在框宽里自动回流的整段 | 同上 + **框宽框高（画布上直接拖框把手）**、两端对齐、首行缩进、标点避头尾（严格/宽松/无）、超框策略 |
| 线段 `line` | 分隔线、下划线、菜单里的引导点线 | 两端坐标、颜色、粗细、样式（实线/虚线/点线/点划线/长虚线）、点距、端头 |

价目表里「菜名 ……… 价格」这一行**不是一个特殊类型**，它就是三个图层：菜名（点文本）+ 引导点线（点状线段）+ 价格（右对齐点文本）。
人可以在浏览器里直接拖字、改字、调样式、拖线段端点；AI 可以直接改数据块。同一份数据能导出屏幕图、印刷图、透明文字层。

**输入通常是两张图**：
- 参考图：最终效果（文字可能是乱码，以它为准定位置/字号/颜色/字体感觉）
- 无字底板图：同尺寸、同版面、但文字已抹掉的图 —— 直接当 HTML 背景

**两图都有的字＝背景，不是待办。** 底板和参考图里一模一样的一些字（标题、印章、装饰文字，差值为 0）量不出来，这是**对的**：它们本来就画在底板上，就该留在底板上。**不要写脚本去擦底板、也不要再补一层一样的字**——那样同一句字会出现两遍（重影），实测有一次转换为此手写擦图/量区脚本白烧了十几分钟。正确做法是照常交付量到的那些层，在交付说明里写一句「这几处字在底板上，要改得重画底板」。`probe` 每次跑完也会把这条口径打在屏幕上。
底板必须真的没有**要改的**字。若底板残留了本该被图层替换的文字，导出的图会出现两套文字叠在一起的重影（先用 `overlay.ps1` 的差异热图确认）。
**残留文字还直接量不出来**：`probe.cjs` 靠两图相减找字，底板上还留着字的地方差值为 0，那一块就不会出现在结果里。
用户只给一张图时：要么请他去字后补一张底板，要么就用参考图当底板并把要覆盖的区域用 `bg` 色块盖住（说明这个限制）。
半张有字半张没字（常见于"只让补下半张"的稿子）：量到的那一半照常做，烙着字的那一半如实说明只能整张重做底板。

## 工作流程

**先量图，别先看字。** 整条链子上最耗时的从来不是排版而是"从像素上把每行字的位置/字号/颜色量出来"，
这一步 `probe.cjs` 一条命令就干完了（4032×2616 的菜单 5 秒、107 行全带点距）。
**不要自己再写像素脚本**（读 PNG、投影、取色这些它都做了），也不要凭眼睛估坐标。

### 0. 默认走这条：一条命令跑完整件（分两段，中间填字）

```bash
node scripts/run.cjs --ref 参考图.png --board 底板.png --out 产物目录 --name 价目表
```

**默认只交图层稿那一个 html**：成品图 / 透明文字层 / 印刷 PDF / PSD 可改字 / 分层 SVG 都在**页面「导出…」里点**，
不要替他跑命令行版（五样合计约 24 s、49 MB，而且他多半会在页面上重新点一遍）。
只有他明确说"命令行给我出一份/要批量出"时，才加 `--exports jpg,text,pdf,psd,svg`。

**第一段**跑 量图 → 校字号，然后**自己停下来**：还有 `"?"` 层没填字就只出骨架 + 裁图，并把"该搬哪份旧稿、
该读哪几张 `sheetNN.png`、是哪几层号"一次列清楚。字有了之后**再跑同一条命令**、加上 `--from "<那份 scene.json>"`，
**第二段**接着往下走：认字体（`fontid --apply`，认得准直接把那一家写进 scene）→〔只有拿不准才回到整页比选 `fontpick --max 3 --apply`〕 → 建稿 → 出图 → 比还原度 → 出全部产物
→ 打一份「绝对路径 + 这是什么 + 关键数字」的交付清单（§6 要的就是这份）。
旧版实测一份 316 层的菜单：第一段 3.2 秒；字已备好时**带 `--map` 一把跑完 73 秒**（当时认字体 8 秒顶掉了整页比选，同一件不认字体要走 246 秒）；同一件按 §1~§5 分散调用是 2540~2569 秒
——差的全是模型来回的轮次，不是脚本时间。

填字两条路，按顺序选（细节见 §2）：**① 有上一版就 `--from 上一版.html` 搬字**（按锚点搬 `text`/`font`/`weight`，实测整件 94 秒，连字体都搬来了所以第二段不再选字体）；**② 全新稿**对着 `sheetNN.png` 写一份纯文本清单，交给 `fill.cjs` 或直接 `run.cjs --map 填字.txt`。
**别手改 `scene.json`，也别在转换里现写填字脚本** —— 2026-09-28 查一次 WorkBuddy 实录：那 8 分钟全花在临时 `fill_scene.cjs` 上。
**不用任何 OCR**（2026-09-28 按用户要求移除：读空的那 10% 会让跑的人自己写脚本补，比它省下的 10 秒贵得多）。
参数见 `scripts/run.cjs` 文件头；只要其中一步就照 §1~§5 单独跑那一步。

### 1. 一条命令量完全图

```bash
node scripts/probe.cjs --ref 参考图.png --board 底板.png --out probe --cluster     # 有旧稿再带 --from 上一版.html
```

它把 `|参考图 − 底板|` 当探测器（白字黑底、红底金字、任意颜色都能量），递归 XY 切分找出每个差异块，输出：

- stdout：文字块一行 `kind / x0..x1 / y0..y1 / 墨迹高 / 建议字号 / 行距 / 行数 / 字色 / 底色`（带引导点线的行还标 `点线N个/距M`），线段块一行 `### line (x,y)→(x,y) 粗N 样式 dash=… 颜色`
- `probe/scene.json`：**图层骨架**，位置/字号/行距/颜色都填好了；「菜名……价格」已经拆成 点文本 + 线段 + 点文本 三层。文字的 `text` 是 `"?"`，按 §2 那两条路填（搬旧稿 / 读裁图）
- `probe/sheet01.png …`：把每块的字裁出来堆成几张图，复核时看这几张（按高度预算合并，一份百来块的菜单两三部就看完；线段不进裁图）
- `probe/blocks.json`：全量细节（含每一行的框、每块的 `fits`），要写批处理脚本时读它

自动处理的事，不用再手动确认：两图给反了会自己换回来并打印正确参数；色块这类"图形差异"会被跳过并计数；
细长的差异带（分隔线、下划线、点线）会被认成**线段**并按墨迹量出粗细、点距、样式（实线/点线/虚线）；
同栏价格右端自动对齐；`yink` 自动开（量到的都是墨迹）。

参考图与底板**必须同尺寸**，否则它直接报错退出 —— 先 `shrink.ps1 图.png` 核对宽高。
**格式不用先转**：webp / heic / jpg 都会先由系统自带的 WIC 摊成无损 PNG 再量（`flat.cjs` + `img2png.ps1`，
缓存到源图旁的 `_src/`，`probe` / `build` / `fontpick` 共用同一份）。但**有损格式会抬高底噪**：
同一张 4032 菜单，PNG 在 `--T 24` 量到 322 块，只有 jpg 时只量到 6 块（噪点把行连成一坨），
`--T 45` 才 65 块、`--T 60` 才 107 块。所以底噪超过 4% 时它会打印那条 ⚠ 并建议 `--T`，
**能向出图方要 PNG 就要 PNG**，别拿 jpg 当参考图。底板纸色和参考图不一致时会自动按逐通道中位数白平衡拉平
（实测不拉时整片纸都算差异，差异像素 99.62%、只量到 1 块；拉平后 6.79%、105 块 + 1 根线段），`--nobalance` 关掉。
只给了一张图时它退化成单图墨迹模式（自动判极性），但底板残留文字会一起被量出来，说明这个限制。

设计坐标 = 底板图像的像素尺寸（`build` 会自动读取，不必手填）。

### 1b. `--cluster`：把"其实只有一套"的参数收成一套（推荐每次都带）

一份稿子里字色、底色、线宽、点线点距**本来就该是一套**，逐块各量会把一套量成几十个错值
（抗锯齿、字数少、边缘糊）。`--cluster` 做四件事，跑完在 stdout 打一张台账：

- **并颜色/底色**：按色距并簇（阈值 18/255 ≈ 一个抗锯齿色阶），`#1b1c1e`/`#181a1c` 收成一个 `#17181a`
- **并线宽与点距**：108 条引导点线的点距量出 15/16/17 混着排，进 PS 一眼看不齐，并成一个
- **打角色名**：按字号档位 + 是不是引导行的菜名/价格 + 多行段落，写进图层 `name`（`菜名 / 价格 / 引导点线 / 标题 / 段落`），
  配合顶栏「快速选择」和面板，**整批调**才有着落
- **公共值收进 `scene.text`**：和默认值相同的 `size`/`color` 从层里删掉，改一处整类跟着动。**这只是换个地方存**——
  菜单稿 322 层里字号等于公共值 55 的只有 21 层，把它们删掉改写进 `text.size` 后两份稿子 4032 渲染 MD5 逐字节相同；
  "只并得动 21 层"这件事本身就是字号并不统一的证据

**字号默认不并**，这是实测出来的结论（4032 菜单稿、210 个文字层、拿交付件真值对比）：

| 做法 | 中位误差 | 误差>5% 的层 | 不同字号数 |
|---|---|---|---|
| 只按墨迹高估（不 `--fit`） | 1.9% | 46/210 | 9 |
| `--fit` 逐层按墨迹宽反解 | **1.1%** | **15/210** | 39 |
| `--fit --cluster`（同上，只多一张离群清单） | 1.1% | 15/210 | 39 |
| `--fit --cluster --unify`（并字号） | 1.6% | 17/210 | 30 |

**为什么并字号反而更差**：AI 画的参考图里"同一档"字号**本身就不统一**——这份菜单的真字号有 **49 个不同值**（43.3~62.6）。
并成一套省下的是"要复核的条目数"，赔的是和参考图的对位还原度，而还原度是这套东西的第一判据。
所以要**并**（源图是干净矢量导出、字号真是一套时）加 `--unify`；默认只报不并。

**准确率最大的一档其实早就有了、只是容易被跳过：`--fit`。** 字填进去之后按"墨迹宽 ÷ 字数"反解，
误差>5% 的层从 46 降到 15。所以**填完字必须跑 `--fit`**，别拿墨迹高估的字号直接 build。
`--fit --cluster` 还会额外列出"和自己那一套差 6% 以上"的层——要么真是例外，要么这层的字读错了，正是该人工看的地方。

### 2. 填字：先搬上一版，全新稿写一份清单交给 `fill.cjs`（两条路，都不用 OCR）

**① 有上一版就别再读一遍字。** `--from 上一版.html`（也可以直接指上一份 `scene.json`）就是当年 `probe/fill.cjs`
干的事，现在进了技能本体：按**锚点就近一对一**（容差 `--fromtol 14` 设计像素，坐标按新旧设计尺寸等比缩放）
把旧稿里核对过的 `text` 和 `font`/`weight` 搬到这次量出来的层上，配上几层、搬了几层都会打出来，**以旧稿为准**。只搬"量不出来的东西"——坐标、字号、颜色仍以这次像素量出来的为准（搬旧的反而是退化）。
实测把成品重新渲染再量一遍：210 个文字层全部配上、文字 210/210 与真值一字不差，量图加搬字 **3.6 秒**；
一层都没配上时它会明说"版式挪过，别带 --from"。字体也一起搬过来了，所以第二段不再选字体。

**② 全新稿（没得搬）对着裁图写一份清单，交给 `fill.cjs`。** `probe` 把每个文字块裁出来堆成 `probe/sheet01.png …`（按高度预算合并，一份百来块的菜单只有两三部；线段不进裁图）。**先打骨架、再照骨架写清单**，不要手改 JSON：

```bash
node scripts/fill.cjs --scene probe/scene.json --dump > 填字.txt     # 待填层一行一条：「124,216 ?」
node scripts/fill.cjs --scene probe/scene.json --map 填字.txt                # 填完自动接着 --fit 校字号
```

清单每行 `位置 文字` 或 `层号 文字`（`#` 开头是注释）。**原来粘成一块的那一行写成 `82,711 大小米饼（8M+）……27 元`**，它自动拆成 菜名 + 引导点线 + 价格 三层，点线的粗细/点距/颜色照抄同稿里已有的引导点线。规矩：

- 段落按参考图的换行处写 `\n`；**线段层没有字要填**（一份菜单里 50~110 根线段一层都不用动）
- 拆出来的新层**一律追加在末尾**，不插在中间 —— 层号一挪，`blocks.json` 的 `fits` 就对不上号，`--fit` 会拿别人的墨迹宽算这层的字号（实测把 55 推成 153）
- **只改 `text`**，别动 `x/y/size/color` —— 那些是从像素上量的，比眼睛准
- 填完跑 `node scripts/probe.cjs --fit probe/scene.json --cluster` 按墨迹宽重算字号（误差 >5% 的层从 46 降到 15），
  它会顺手列出"和自己那一套差 6% 以上"的层——要么真是例外，要么这层的字填错了，正是该回看的地方
- 然后 `run.cjs … --from probe/scene.json`（或 `--map 填字.txt`）接着跑第二段（§0），**不要**重新量图
- 字还没填时 `fontid.cjs` 只能给个方向（笔画几何），认字体要在填完字之后跑

**没有 OCR 这条路（2026-09-28 移除）。** 以前 `--ocr` 会用 Windows 自带的 `Windows.Media.Ocr` 先读一遍，
实测 82% 一字不差 / 8% 读错（形近字与偏旁）/ 10% 读空。读空那几十层最后还是要人回裁图核对，而核对过程中最容易
诱发"自己写个脚本补一下"——一次真实转换为此白烧了二十几分钟。所以宁可老老实实读裁图。

骨架已经判好类型了，只在明显不对时改；三种层的取舍：

| 点文本 `point` | 段落文本 `para` | 线段 `line` |
|---|---|---|
| 标题、菜名、价格、标签、按钮、单行说明 | 正文、描述等要在框内自动换行的 | 分隔线、下划线、菜单里菜名和价格之间的引导点线 |
| 改内容只会左右变宽，永不换行 | 必须给 `w`（框宽），超宽自动折行 | 给 `x y x2 y2`（或 `x y len`）+ `width` `style` `color`，`dash` 可精确到"画几个空几个" |
| 多行列表（每行独立）→ 每行一个 point | 一整段文字 → 一个 para | 一列菜单的引导点 → 每行一条 `style:"dotted"` 的线段，`dash` 整列一致 |

字段与取值规则见 `references/scene-schema.md`（必读：字体与字重的坑在第 6 节，`yink` 的语义在第 4 节）。

填完字再跑一次校准：

```bash
node scripts/probe.cjs --fit probe/scene.json
```

骨架里的字号是按**墨迹高**估的，会随字体不同偏 5% 上下；这一步改用「墨迹宽 ÷ 字数」重算（全角算 1 em、半角 0.55），
和参考图的对齐精度到 1% 以内。**没填字的层和线段层会被跳过**，所以一定要先填字再 fit。

### 3. 认字体 → 选字体（只用本机已装字体）：先认是哪一家，再只在它里面比

`probe` 量图时已经按字号把文字分了**层级**（`scene.layers[].lv`，一档＝一个层级，容差故意给到 18%——
AI 稿同一档字号本身带 ±5% 抖动，切太细会把同一个设计意图拆成十几档，选字体就又变回逐层比选）。
**第一步是认字体**（`fontid.cjs`）：拿**已知的那个字**在当前机器的候选家族里逐家画一遍，每格按墨迹外接框归一到 32×32，和参考图里切出来的同一个字比 IoU —— 一次画完不渲染整页。候选直接取 GDI 可绘制的家族，避免扫描全部字体文件和把绘不出的家族占进候选池；JPG/WebP 参考图先转 PNG 再解码。4032×2616 菜单样例认字体约 **3.8 秒**（原约 7.8 秒），有效比字形 259 个（原 60 个），切不开丢掉 10 段（原 89 段）。

```bash
node scripts/fontid.cjs --scene probe/scene.json --ref 参考图.png --apply     # run.cjs 第二段已经自带这一步
```

旧版的分类样本实测（候选＝系统各类名各占一席 + 思源／冬青／Noto 各点名补一席，约 20 家；2026.09.28-6 换候选来源后还没重跑这组六类）：
**黑／宋／楷／仿宋／圆／隶 六类各画一张真图来认，六类全认对**——隶书 0.792（甩开第二名 0.443）、楷体 0.707(+0.363)、幼圆 0.687(+0.19)、宋体 0.632（与新宋体并列，本来就是同一设计的两种点阵口径）、仿宋 0.583(+0.145)、黑体那例第一名是思源黑体 0.619（与黑体同族）。
拿 Chrome 渲染的成品当参考（真值 `思源黑体 CN`）→ 第一名 `Noto Sans SC` 0.749、第二名 `思源黑体` 0.745：这俩是同一套字形的两种打包，**并列就按第一名定**，视觉无差。本机 9 家中文字体 × 2 个字号另有结论：**30px 以下整体压到 0.3~0.45、名次会抖**（笔画只有 1~3 px，量化把差别抹平了）。
所以「认得准」＝ IoU ≥ 0.5 且（甩开第二名 ≥ 0.06 **或与第二名是同字形发行别名**）才 `--apply` 直接定；微软雅黑和思源黑体虽然都是黑体，但不算同字形别名。分数咬得近又不是别名，就只把候选缩到前三名交给下面的比选。
两个必须记住的坑：① **候选池的组成比算法更要命** —— `黑体-繁`、`思源黑体 CN Bold` 这类前缀命中能把十几个位子占满，把「幼圆／隶书／等线」挤出去，于是同一份宋体稿从认出 `宋体 0.632` 掉成只认出 `华文中宋 0.536`；现在的规则是类名**正好等于**系统类名的排最前，再点名补 思源黑体／思源宋体／Noto Sans SC／Noto Serif SC／冬青黑体 各一席。② 隶书／魏碑是系统里的正经类别，**不再当装饰体排掉**（草书／行书／手写／艺术体仍排掉）。
几何比值（横画均宽 ÷ 竖画均宽）只是**没有已知文字时的方向**：宋体/新宋体/华文中宋 0.33~0.67 ＝横细竖粗，黑体/微软雅黑 0.8~1.0 ＝等粗；仿宋、楷体、以及 30px 以下的一切，比值都贴着 1.0 分不开 —— 分六类靠比字形，别拿比值当结论。

第二步才是按层级比差值，用 `fontpick.cjs`（有 `fontid.json` 时它自动只比认出的那几家，`--nofontid` 才回到全库自动挑）：

```bash
node scripts/fontpick.cjs --scene probe/scene.json --ref 参考图.png --board 底板.png --apply
     # 可选：--cands 宋体,黑体 指定候选 ｜ --levels 1,2 只换那两档 ｜ --max 3 每档比几套 ｜ --list 只看候选
```

它自己挑候选（要求含所需字重、排除手写/艺术体这类装饰字体、常规字重优先、非 CFF 轮廓优先、名字短的优先），
每套各渲染一遍 `--width` 宽度的图并用 `overlay.ps1` 量差值，按"明显差异像素"排名，`--apply` 把冠军写进
`scene.layers[].font` 与 `scene.text.font`。**不要**手动改一处 build 一次再看数字——那是十几轮往返，每轮几十秒模型延迟。
实测 3 套候选 2 分 53 秒出排名，冠军 `思源黑体 CN` → 9.62% / 平均差 12.1（和手调基线一致）。

字体家族名一律用 `fonts.cjs` 里查得到的**本机已装**家族：

```bash
node scripts/fonts.cjs --filter "宋|黑|楷|雅黑"        # 家族名<TAB>可用字重
```

**并且该家族必须有你要用的字重**（参考图是粗体就得选含 700 的家族）；单字重家族写 `weight:700` 会被浏览器合成假粗，大字直接糊出重影。

### 4. 生成图层稿

```bash
node scripts/build.cjs build --scene probe/scene.json --board 底板.png \
     --ref 参考图.png --out 稿.html --dpi 300 --fonts auto
```

- `--fonts auto` 会把本机字体表与每族可用字重内联进 HTML，并在 build 阶段警告不可用字重
- `--dpi` 用于反推印刷尺寸（`--page 420x297` 可直接指定毫米）
- 底板与参考图都会内联成 data URI，产物是**单文件**，可直接发给别人打开

### 5. 校还原度（必做，不要跳过）

```bash
node scripts/export.cjs 稿.html --width 4032 --format png --out chk    # --width = 参考图原生宽度
powershell -File scripts/overlay.ps1 -Render chk-4032px.png -Ref 参考图.png -DiffOut diff.png
```

**一定要按参考图的原生宽度出图再比。** 拿 2k 缩略图去对 4K 参考图，脚本重采样会把参考图的字抹平，
同一份稿子能从 7.9% 被判成 15.5%，看起来像改坏了。

`overlay.ps1` 输出平均差值、明显差异像素比例和一句判定。偏差明显时按差异热图定位：
- 差值集中在字形边缘 → 字体或字号不对
- 整块偏移 → 改 `x`/`y`/`dy`
- 只有某几行错位 → 那几个元素的问题

改 `scene.json` 后不必重新内联图片：

```bash
node scripts/build.cjs set --html 稿.html --scene probe/scene.json
```

（改了 `assets/stage.html` 引擎就得重新 `build`，`set` 只换数据块。）

**一轮只看一次热图。** 位置类的问题 probe 已经量到位了，剩下的基本是字体本身不像；
成片的字影才动 `x/y/size`，零星的字形差异不要动。反复 2~3 轮封顶。
参考图是 AI 出的图时，字形与任何本机字体都不是一族，**8~10% 明显差异像素就是正常水平**，
别为最后几个点反复折腾；判"够不够好"看热图里文字处是否还有成形的字影。


### 6. 交付

**收尾必须在对话里把产物列出来**（用户 2026-09-27 要求）：一条一行，**绝对路径 + 这一份是什么 + 关键数字**，
不要只说"已生成"、也不要让人自己去翻目录。默认交付就这两份 + 一句还原度：

```
F:\...\价目表-图层稿\价目表.html   ← 图层稿（双击打开，点「编辑」改字），322 层 / 6.63MB
F:\...\价目表-图层稿\scene.json     ← 可改的源数据
还原度：明显差异像素 9.62%，判定「版面已吻合」
要成品图 / 透明文字层 / 印刷 PDF / PSD 可改字 / 分层 SVG：在页面「导出…」里点（4K/8K/16K 都有）
```

他明确要过命令行产物（或加了 `--exports`）时，才把那些一行一行补进清单；只做了其中几样就只列几样，没做的别列。
改过一轮再交付时把**变化的那几行**重列一遍（路径不变也要重说一次数字）。

告诉用户界面分**三区**：
- **顶部工具条**只留全局开关（固定一行，放不下就横向滚；它下面另起一行显示状态提示文字）：撤销/重做、编辑、
  ＋文字/＋线段、删除、清空格子、**快速选择 ▾**、视图缩放、吸附、换底板、叠影/差值/网格、**导出…**
- **画线段（「＋线段」）是两点画法**：点按钮进入画线态（画布十字光标），**单击画布定起点 → 移动鼠标就有一根线跟着走 → 再单击收口**；按住 **Shift** 锁成水平或垂直（按离起点哪个方向更远判），**Esc** 作废这一笔（临时层直接删掉），画到一半再点一次按钮＝替他收口。起点落在画板外（灰边、右栏、工具条）一律不落点。收完口就是普通线段，两端把手照旧可拖
- **左边画布区**：画板居中、自己滚动
- **右边工具栏**（只在编辑态出现，用「面板」按钮收起后画布拿回整条宽度）常驻四块：属性面板＋轮廓描边、
  **对齐与分布**（10 个图标 + 组合/拆组/全部拆组）、**复制 · 粘贴**（复制图层/粘贴/原位粘贴 ＋ 属性刷三件套）、**🔒 锁定 / 解锁全部**。
  没选中图层时这些按钮自动灰掉。本机字体表**不是**栏底的一节，而是点「字体」框时**就地浮在框子下方**的一层下拉
- **「导出…」是弹窗**：格式 JPG/PNG、4K/8K/16K 图片、透明文字层 PNG、印刷 PDF、**PSD 可改字（印刷版 / 通用版两个按钮）**、**分层 SVG（活字）**、下载 HTML 都收在里面；弹窗底下一条「**线段转形状图层**」勾选框（默认勾上），管两条 PSD 路径里的线段是形状层还是像素，
  点完出图自动关闭（Esc 或点卡片外的遮罩也关）
- 双击打开 `稿.html`，点「编辑」后：**单击**选中、**Shift 单击**加选、**Ctrl 单击**减选、**空白处按住左键拖框**批量选、
  **空白处单击**或 **Esc** 取消选择；选中一批后，拖动、方向键微调、右侧面板改参数、删除、换字体都同时作用到这批。
  **框选看拖动方向**（同 Illustrator / CorelDRAW）：**从左往右＝碰到就选**（只压到一角也算），**从右往左＝整层被框进才选**；
  状态行每次都会报当前用的是哪一种，方向只认横向，上下拖不变口径。**框选的起点必须落在画板里**——从画板外的灰边起手再拖进画板不算框选（不出橡皮筋、不选任何层）
  **顶栏「快速选择 ▾」**＝一次选光一整类：全部文本 / 全部线段 / 与当前选中层**相同填充颜色**（字色或线色，浮层里带色块），
  下拉就在按钮正下方展开，锁住的层和文字被清空的空格子自动跳过（状态行报跳过几个），选完直接整批改参数、对齐或删除；
  自动进入编辑态，`Esc` 或点外面收起浮层
  **锁定**：选中后按 `L`（或点「🔒 锁定」）—— 锁住的层不再吃鼠标，单击/框选都绕过它，也就拖不动、选不上、改不了，
  但照常参与导出；`Shift+L` 或「解锁全部」放开全部，Alt 单击某一个＝只就地解锁它（锁着时状态行会提示这几条）
  （位置类字段按"位移"下发，不会把大家叠到同一点）
- **撤销/重做**：`Ctrl+Z` / `Ctrl+Y`（或 `Ctrl+Shift+Z`），工具条上也有 ↶↷ 按钮。整份图层数组当一步历史，
  留 80 步；面板里连续打字用 350ms 防抖合成一步，所以"改回原样"只需按一次。**只有 Delete 删除选中图层**（`Backspace` 不删，它在主键盘上误按一次就少一层，只在编辑文字时改字），删完照样能撤销；
  这条快捷键只让位给"**正在打字**"（焦点只是停在面板某个框里、没敲过字时照样删图层），就地改字和文字/数字框里则删的是字
- **右侧面板只显示当前这一类图层用得上的参数**：选中文本只有字体/字号/行距/字距/颜色/对齐等，选中线段就换成两端坐标
- **段落文本有一套自己的排版参数**（选中段落时面板才多出这块，点文本完全不显示）：
  **对齐四种**＝左对齐 / 居中 / 右对齐 / **两端对齐**（`align:"justify"`，靠**解出来的字距**把每行拉到框宽，
  只放不收、末行永不拉、空行跳过，所以数字串那么长也不会被压扁）；**框宽 / 框高**（按 pt，和数据块里的设计像素换算）；
  **首行缩进**（`fi`，只缩每段第一行，`\n` 之后算新段）；**标点避头尾**（`kin`）＝**严格**（默认，禁则标点被上一行拽下来）/
  **宽松**（标点允许悬挂在框外）/ **无**（按宽度硬断）。**画布上段落会画一个可拖的框**：右/下/右下角三个把手，
  外加**贴在四条虚线边上的四条透明边条**——压在哪条边上就动哪条边，拖左边和上边时左上角跟着走、对边钉住
  （框内部仍然不吃鼠标，否则点不到里面的字）。拖动途中即时回流、每帧只重画这一层，松手才落一步历史（`Ctrl+Z` 一次回到拖之前）；
  拖过框后 `fit:"grow"` 会自动收回 `wrap`，否则框会自己长回去。
  两端对齐/缩进/避头尾都走同一套 `layout()`，所以屏幕、画布导出、PSD、分层 SVG 四份产物一致
- **字号与描边宽度在面板上按 pt，一个框两用**：框里**直接打字**就照 pt 生效，点框内的 **▾** 弹出预设挑
  （字号 6/7/8/9/10/11/12/14/16/18/24/36/48/72/100/150/200，粗细 0.1/0.3/0.5/1/2/3/4/8/10/12/16/24/36/48），
  浮层开着时打字＝过滤这份预设列表；当前值刚好是预设会在列表里标绿。**不摆"下拉＋输入框"两个控件**。
  **数据块里仍然存设计像素**，换算系数 = `design.w ÷ (page.wmm/25.4) ÷ 72`；稿子没有 `page` 时退回头看板像素，标签跟着写 `(px)`
- **轮廓描边**（右侧工具栏里那一组）：给文字加一圈真描边。宽度就是开关（改 0 整组自动清空），另有
  颜色、风格（实线/虚线/点线/点划线/长虚线）、自定义虚线节奏，点「…」再展开**端头 / 拐角 / 斜接限制 / 位置**；
  位置三种＝**外侧（默认，字保持原粗细向外扩）** / 居中（压在笔画上，字显粗）/ 内侧（只在笔画内部，字不变大）。
  **同一组控件也服务线段**：选中线段时它的颜色/粗细/风格/虚线/端头就在这几行里（拐角与位置对线段没意义，会自动藏掉）
- **复制 / 粘贴图层**（右栏「复制 · 粘贴」第一行，或 `Ctrl+C` / `Ctrl+V` / **`Ctrl+Shift+V` 原位粘贴**）：整层深拷贝，
  文字、位置、字体、描边、组合关系都带着走。**组号一定换新**（`nextG()`＋一张 `旧组号→新组号` 的表），否则新层和原层同号＝
  同一个组，拖一层会把两组一起拖走；复制来的层不带 `lock`。普通粘贴向右下错开"一格"（版宽/100，菜单稿＝40 设计像素）好让人
  看见贴了几份，原位粘贴坐标一字不动（做个底层压色、留份改字重的副本用得上）。剪贴板是**页内**的：要跨软件继续改，走 PSD / 分层 SVG 导出
- **属性刷**（右栏「复制填充 / 复制轮廓 / 复制全部」）：先选中当源的图层，点按钮，再去点要刷的目标，可连点多个，
  **Esc** 结束。种类不同也能刷（线段的颜色粗细会换算成文字的描边）；**位置、文字内容、图层类型、组合关系永远不带过去**
- **换底板**：换一张背景图，所有图层坐标一律不动；新图尺寸与版面设计不一致时按设计尺寸拉伸并在状态栏报出两个尺寸。
  图片重新内联，`Ctrl+Z` 能换回来，要点「下载 HTML」才落地
- **文字被清空的图层＝空格子**：画面里看不见却还占着原来的框，会把鼠标"吃掉"，出现"这块明明没东西却要双击好几次才选中"。
  现在它自动隐身（不描边、不响应鼠标、框选也跳过后），工具条「清空格子」一键盘掉，或 `Ctrl+Z` 把字撤回来
- **视图缩放**：在画布上**直接滚滚轮**就缩放（钉住光标下那点，Ctrl/⌘+滚轮同效），**Shift+滚轮**横向平移，
  **空格+拖动**或**鼠标中键拖动**平移；工具条上还有「适应 / 100% / －／＋ / 面板」。
  缩放只改 `transform`，坐标仍是设计坐标，导出与打印版面不受影响
- **右栏「对齐与分布」**（10 个图标按钮）：左 / 水平居中 / 右 / 顶 / 垂直居中 / 底（**多选以第一个选中的层为基准**，
  它带一圈品红虚框；框选和「快速选择」是一次性命中、没有先后，退回按选区外接框对齐；单选贴画板）、
  纵向等距 / 横向等距（≥3 个单元，两端钉住、中间间距调成一样）、水平/垂直居中于画板；
  **选中里有组合时按"整组"为一个单元**移动与分布，组内相对位置不会被拆散
- **Shift+拖动＝只走水平或垂直一个方向**（中途可按/松切换，锁住的那一轴不再吸附，不会被拽偏）
- **吸附**（「吸附」开关，默认开）：拖动时贴齐画板四边两中线与其它图层的边/中心，吸住瞬间出现品红色参考线；
  **按住 Alt 临时忽略吸附**做精细微调。容差按屏幕 6 像素算，所以缩得越小吸得越"松"
- **组合 / 拆组 / 全部拆组**（Ctrl+G / Ctrl+Shift+G / Ctrl+Shift+A，拆组时按 Alt＝全部拆）：
  数据上是扁平的组号栈 `g:[1,2]`（内层在前），所以组可以嵌套 —— 先把 ac 组合、再把 ac 和 bd 一起组合，
  **拆组只退最外面一层**（ac 仍是组），全部拆组才散成 a、b、c、d。组合只改"选择单位"，坐标仍各自独立，
  排版与导出完全不受影响；组合后点任意一层整组选中、整组拖动，**对齐与等距分布按整组移动**（组内相对位置不动），
  **Alt 单击**穿透整组只选一个
- 选中线段时线上会出现两个端点方块，拖端点单独改一头；「＋线段」新建一条线，「＋文字」新建文本
- **换字体也只有这一个框**：点它（或点框内 ▾）**就在框子正下方浮出本机字体表**＝就地下拉，直接点名字选；
  打字即过滤（每行用该字体本身预览），回车取过滤结果第一项，输完整家族名后移开焦点也认。
  行右边的数字是**该家族真实存在的字重**，点数字连字重一起换（没有的数字不会出现，避免浏览器合成假粗）。
  多字重的家族排两行：第一行整条都是字体名，第二行是字重芯片；**一档最多先给 6 个，其余收成「+N 档」，点它只展开这一行**（不换字体）。
  只有单一字重的家族不占第二行，列表因此更密；要只看有字重梯度的，勾浮层顶上的「只看含多种字重的」。
  选完浮层不收起（方便连着挑），滚右栏 / 点别处 / Esc 收起
- 顶栏「导出…」弹窗里可出 4K/8K/16K（JPG/PNG）、透明文字层 PNG、印刷 PDF、PSD（印刷版/通用版）、分层 SVG、下载改好的 HTML
- 要拿去 **Photoshop 改字**：导出弹窗里有 **「PSD 可改字·印刷版」**，点一下就下载 PSD —— 文字是**活的文字层**
  （可直接改内容、字号、颜色、描边、位置），底板是位图层、**线段是形状图层**（PS「直线工具」那种：能拖端点、能改粗细/颜色/虚线），另带一张整版压平预览。
  两版字号相同（都写设计像素，PS 排版时把 1pt 当 1 像素用，实测它不按文档分辨率换算 pt），只差文档分辨率元数据：
  **印刷版**把分辨率写成稿件真实值（菜单稿 300），PS「图像大小」里纸张就是 scene.page 的毫米数，印刷商要这个；
  **通用版**写 72，给 Illustrator / CorelDRAW / 看图软件那类真按 dpi 换算 pt 的应用用，字画得一样大
- **PSD 里带 Photoshop 自己的两种对象**（不是"能打开就行"）：HTML 里 `Ctrl+G` 合过的组，进 PSD 就是**图层编组**
  （照图层 `g` 组号栈建树，嵌套也照搬；组是 `pass through` 混合模式，和 PS 自己新建的一模一样）；
  `kind:"para"` 的那层进 PS 就是**段落文本**（不是点文本）—— 带框宽框高，进 PS 可以直接用文字工具拖框、改字重新回流，
  **首行缩进**跟着 `firstLineIndent` 走、**避头尾·宽松**走 `burasagari`（标点悬挂）。"无"这一档 PS 没有对应开关，只能不给。
  **段落层送的是原文，不是页面折好的行**：把折行用 `\n` 拼起来送进 ag-psd 会被编成 `\r`＝硬回车，PS 里改框宽就不回流、断行点和页面各排各的；
  同时给 `everyLineComposer`（逐行合成器）让 PS 的断行尽量贴页面——合成器与禁则不可能和 PS 一字不差，差几处属正常
  口径全部从用户机器上的真实 PS 稿回读出来照抄，不要自己猜字段
- 要在 **Illustrator / Inkscape / Figma / Affinity** 里逐层改：点 **「SVG（分层·活字）」** —— 一个图层一个 `<g>`，
  文字仍是活字。这是最稳的落点：SVG 的 font-size 就是用户单位，1:1，没有任何软件会去换算它
- **PDF 里的文字能不能改，取决于字体轮廓类型**，不是取决于导出设置：本机装的**静态 TrueType**（黑体、微软雅黑、楷体、宋体…）会被 Chrome 嵌成
  `Type0 + CIDFontType2 + FontFile2` 真活字；**CFF/OTF**（思源黑体 CN 就是 `.otf`）、**可变字体**、以及**内联的 @font-face 子集**一律写成 **Type3**
  （显示、印刷、搜索、复制都正常，但 Illustrator 打开多半转成轮廓）。`build --fonts auto` 会自动体检并在数据块里记 `cff:[家族…]`，
  页面点「印刷 PDF」时状态行会提醒一句；要在别的软件逐层改字就用上面那条 SVG
- 页面里的改动要点「下载 HTML」才会存盘（会下载一个包含全部改动的新单文件）
- 需要 AI 再改：直接编辑 HTML 里的 `scene` 数据块，或改 `scene.json` 后跑 `build set`

命令行批量出图：

```bash
node scripts/export.cjs 稿.html --width 4k --format jpg     # 4K 成品图
node scripts/export.cjs 稿.html --width 8k --layer text     # 8K 透明文字层，用户自己合成
node scripts/export.cjs 稿.html --format pdf                # 矢量 PDF（按 scene.page 毫米出纸）
node scripts/psd.cjs 稿.html                                # 默认两版都出：稿.psd（印刷版）+ 稿-通用.psd
node scripts/psd.cjs 稿.html --units print                  # 只出印刷版；--units px 只出通用版
node scripts/psd.cjs 稿.html --lines bitmap                  # 线段退回一层像素（默认写成 PS 形状层）
node scripts/psd.cjs 稿.html --width 4k                     # 放大到 4K（默认自带压平预览，--no-preview 去掉）
node scripts/svg.cjs 稿.html                                # 分层 SVG（稿.svg，底板内联、文字活字）
```

## 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/probe.cjs` | **量图第一步**：`--ref` 配 `--board` 用两图之差找差异，递归 XY 切分，输出块表 + `scene.json` 骨架 + 裁图 + `blocks.json`。自动判两图顺序、把细长差异带认成**线段**（量出粗细/点距/实线还是点线）、把「菜名……价格」拆成 点文本+线段+点文本、同栏价格右端对齐。`--T 24 --gap 16 --lineGap 4 --colgap 60 --maxpx 4200 --emh 0.92`；**填完字必须再 `--fit scene.json`** 按墨迹宽重算字号（误差 >5% 的层从 46 降到 15；`--from` 搬完字会自动接着跑这一步）。`--from 上一版.html｜scene.json` 按锚点沿用旧稿已核对过的文字与字体（见 §2）。`--cluster` 并样式 + 打台账：同组字号差 3% 以内并到组中位数、差 6% 以上单独报出来，字色/底色/线宽/点距照常并，并把公共字号公共色收进 `sc.text`（图层不再重复写）。加 `--unify` 才让整组用同一个字号（**默认不并**，实测并了更差：逐层 1.1% / 并组 1.6%，AI 画的稿子同层级字号本来就不统一，见 §1b），`--nosnap` 只出台账不改值，`--tol 0.03` 调容差。每次跑完打印**样式聚类台账**（每套参数几个层、哪几组没吸附、角色分布），一眼看出这份稿子到底有几套参数。按字号分的**层级**写进 `layers[].lv`（选字体按层级一套一批定，见 §3）。底板纸色与参考图不一致时自动白平衡拉平（`--nobalance` 关）。同一版式重出图时带 `--from 上一版.html`：按锚点把旧稿核对过的 `text`/`font`/`weight` 搬过来，不再读一遍字（§2） |
| `scripts/flat.cjs` | 把 GDI+ / probe 自带解码器认不下的图（webp、heic、avif…）**摊成 PNG**：`flat(路径, { log })`，probe 传 `{ need:'png' }`（不是 PNG 就转）。走同目录 `img2png.ps1`（系统自带 WIC，不装第三方解码器），缓存到源图旁的 `_src/<名>-<字节数>-<mtime>.png`，`probe`/`build`/`fontpick`/`run` 共用同一份。`--noconv` 关掉 |
| `scripts/img2png.ps1` | `-In 源图 -Out 目标.png [-Status 状态.txt]`：WinRT `BitmapDecoder`→`Bgra8`→`BitmapEncoder(PngEncoderId)` 写出 PNG。目标文件必须先存在（WinRT 的 StorageFile 只开已有文件，Node 建空文件）。**状态一律写进 `-Status` 的 UTF-8 文件**：PowerShell 控制台是 GBK，中文报错到 Node 就成乱码。实测本机可直接解 webp（1067×1600 一次成功） |
| `scripts/run.cjs` | **一条命令跑完整件**（§0，分两段）：量图 →（填字：`--from` 搬旧稿 / `--map 填字.txt` 交给 fill.cjs）→ `fontid --apply` 认字体（认得准就**跳过**整页比选，`--force-pick` 才比）→ 拿不准才 `fontpick --max 3 --apply`（带 `--from` 时自动跳过）→ `build` → 出图并与参考图比还原度（比对用的渲染单独占 `名-还原度比对` 前缀，否则 `--format jpg` 会把同名中间 PNG 删掉）→ 按 `--exports` 出产物（**默认为空**：jpg/text/pdf/psd/svg 由使用者在页面「导出…」里点，只有明确要命令行产物才加）→ 打印绝对路径交付清单。不自动读字：还有 `"?"` 层时第一段跑完就停下并列出该搬哪份旧稿/该读哪几张裁图，填完再跑一次同一条命令带 `--from "<那份 scene.json>"` 续第二段。实测 316 层：第一段 3.2s、第二段 99s、搬旧稿整件 94s、**字已备好带 `--map` 整件 73s**（同一条命令不认字体、比选 3 家要 246s） |
| `scripts/fill.cjs` | **填字清单写进 scene**（§2 的 ②）：`--dump` 把待填层打成骨架清单，`--map 填字.txt` 按「位置 文字 / 层号 文字」就近一对一认领并写回；值带省略号点线或竖线（……、···、竖线）的的那一行**，自动拆成 菜名 + 引导点线 + 价格 三层（新层追加在末尾，层号不挪；同时把 `blocks.json` 里这层的墨迹宽改成菜名那段，否则 `--fit` 会拿整行宽除以菜名字数）；填完默认接着跑 `--fit`，`--clamp` 才顺手把离本档中位数 25% 以上的字号拉回来。**取代"每次转换现写一个 fill_scene.cjs"**（2026-09-28 查 WorkBuddy 实录：那一段 8 分钟、7 个临时脚本） |
| `scripts/fontid.cjs` | **认字体**（§3 第一步）：`--scene --ref [--apply] [--pool 宋体,黑体] [--max 18] [--chars 30] [--lv 1,2] [--noglyph]`。① 逐字比字形：调 `glyphsheet.ps1` 把「候选家族 × 已知字符」画成一张表，每格按墨迹外接框归一到 32×32，和参考图切出来的单字比 IoU，按字号层级出前三名与把握；`--apply` 把认得准的档直接写进 `scene`。候选由 `fontfaces.ps1` 列出 GDI 实际可用的字体，并按稿件字重筛掉不相符的粗细变体；只有思源与 Noto 这类同字形别名才视作并列。逐字比对先校验整行字数，再取选中的字符，不能把没入选的字从校验分母删掉。② 没有已知文字时退回笔画几何（横画均宽 ÷ 竖画均宽）只给方向。段落层**按行配对文字**。结果写 `fontid.json`，`fontpick` 自动认它、只比那几家。4032 菜单实测约 3.8 秒，259 个有效字形样本（见 §3） |
| `scripts/fontfaces.ps1` | 从 GDI `InstalledFontCollection` 输出实际能由 `glyphsheet.ps1` 绘制的字体家族名；`fontid.cjs` 用它代替每次扫数千个字体文件，失败时退回 `fonts.cjs` |
| `scripts/glyphsheet.ps1` | `-Chars 字符表 -Fams 字体表 -Out 表格图.png -Map 行号对照.txt`：GDI+ 把「字符 × 字体」画成一张表（一行一个家族、一列一个字符）。两个表都是**「一行一个」的纯文本（带 BOM）**，不走 JSON —— PS5.1 的 `ConvertFrom-Json` 会把数组读成一个字符串；脚本内部变量也别和参数同名（**PS 变量名不区分大小写**，`$Chars` 和 `$chars` 是同一个变量，会把路径覆盖掉）。画之前先对 `InstalledFontCollection`，本机没这个家族就整行作废（不然 GDI+ 悄悄换成 Microsoft Sans Serif 顶上，比出来的分是假的） |
| `scripts/fontpick.cjs` | **选字体一条命令比完**（§3）：**先读 `fontid.json`（认出来的那几家，不再全库挑；`--nofontid` 关掉）**，没有它才自动挑候选（含所需字重、排除手写/艺术体、常规字重与非 CFF 优先）→ 每套 `build set`+`export`+`overlay` 量差值 → 按明显差异像素排名，`--apply` 把冠军写进 `scene`。`--cands` 指定候选、`--levels 1,2` 只换那两档（按 `layer.lv` 层级）、`--max` 每档几套、`--width` 出图宽度、`--list` 只看候选。取代以前"改一处 build 一次看数字"的十几轮往返 |
| `scripts/build.cjs` | `build` 生成/`set` 只替换数据块。内联底板与参考图（webp/heic 先经 `flat.cjs` 摊成 PNG），自动量设计尺寸，反推印刷尺寸，审计字重、线段坐标与**描边字段取值**，并做**轮廓类型体检**（CFF/可变 → 记 `sc.cff` 并警告 PDF 会变 Type3） |
| `scripts/export.cjs` | 无头 Chrome 出图：`--width 2k\|4k\|8k\|16k\|Npx`、`--format jpg\|png\|pdf`、`--layer full\|text` |
| `scripts/psd.cjs` | 出 **PSD（真·可改字文字层）**：`node psd.cjs 稿.html [--out 名.psd] [--width design\|2k\|4k\|8k\|Npx] [--dpi N] [--units print\|px\|both] [--lines shape\|bitmap] [--no-preview] [--no-board]`。**页面里已有两个一键按钮（导出… → PSD 可改字·印刷版/通用版），这条是给批量、放大出图和只要其中一版用的**。字号与行距两版都写**设计像素数字**（实测 PS 排版时不按文档分辨率换算 pt，写 pt 会让印刷版的字小 dpi/72 倍），描边宽度写 Pixels。两版只差文档分辨率元数据：`print` 写「设计像素每英寸」，PS「图像大小」里纸张就是 scene.page 的毫米数；`px` 写 72，给真按 dpi 换算 pt 的 AI/Corel/看图软件用。放大出图时像素数字同比放大。文字层写的是 **PostScript 名**（`facePs`，PS 只认这个）。底板是位图层；**线段默认写成 PS「直线工具」那种形状层**（`vectorMask` 一条开路径 + `vectorStroke` 带宽度/端头/虚线/颜色，字段照抄桌面真实 PS 稿里的形状层，同一层里仍保留位图缓存），`--lines bitmap` 才退回纯像素；文字是活字层（不带位图，PS 自己重排），默认再压一张整版预览给别的软件看。需要 Node 版 `ag-psd`（`npm i ag-psd`，脚本会往上级目录和 `~/.qoder/ag-psd` 找，**不要**把 node_modules 塞进 skill；页面内那条路径用内联进 `stage.html` 的浏览器包，不依赖它）。描边用图层样式（PS 的描边不支持虚线，虚描边进 PS 会变实线） |
| `scripts/svg.cjs` | 出**分层 SVG**：`node svg.cjs 稿.html [--out 名.svg] [--no-xml]`（页面里「SVG（分层·活字）」是同一份产物的按钮版）。一个图层一个 `<g id="L…">`，组名同时写进 `data-name`（Illustrator 读）与 `<title>`（Inkscape / Figma 读）；文字是每行一个带绝对坐标的 `<text>` 活字，线段是 `<line>`（点距走 `stroke-dasharray`），底板内联成 `<image href="data:…">`，所以也是自包含单文件。`width/height` 在写了 `scene.page` 时给毫米、`viewBox` 始终是设计像素；`--no-xml` 去掉 `<?xml?>` 头（有的编辑器只吃 `<svg>` 片段）。排版仍由页面的 `#svg` 模式算，与屏幕/画布/PSD 同一套坐标 |
| `scripts/png.cjs` | 极小 PNG 解码器（8bit、非隔行、类型 0/2/3/4/6），给 psd.cjs 在 Node 里读位图用 |
| `scripts/fonts.cjs` | 枚举本机字体家族与**真实可用字重**、**PostScript 名**、**字体文件路径**与**轮廓类型**（解析 name / OS-2 表与表目录里的 `CFF `）；`--filter`、`--json` 出 `{fonts, faceWeights, facePs, faceFiles, faceCff}`（`facePs` 供 PSD 用，PS 只认 PostScript 名；`faceCff` 供 PDF 体检） |
| `scripts/rows.cjs` | 只量一个**已知区域**时的放大镜（`--rect` 可重复、`--runs` 看每段墨迹高、`--minH 2` 看引导点）；全图测量用 `probe.cjs`，别拿它一块块手量 |
| `scripts/overlay.ps1` | 还原度校验：50% 叠影 + 差异热图 + 平均差值判定 |
| `scripts/shrink.ps1` | 量图片尺寸 / 等比缩小存 JPG |
| `scripts/tojpg.ps1` | PNG→JPG，可指定底色压平透明 |

模板 `assets/stage.html` 是渲染与编辑引擎。不要直接改它来"修一张图"——所有版面信息都属于 `scene` 数据块；
数据块靠 `/*<<<SCENE>>>*/ … /*<<<END SCENE>>>*/` 标记定位，任何注释或文本里都不要出现这两个标记，也不要出现完整的 `<script id="scene"` 字样。

## 常见故障

| 现象 | 原因与处理 |
|---|---|
| 底板上烙着字、量不出来，想写脚本把它擦掉 | **别擦、也别补一层一样的字。** 两图都有的字（差值 0）＝背景，本来就该画在底板上；擦了再补会出现两套字叠成重影，而且擦不干净。照常交付量到的那些层，在交付说明里写一句「这几处字在底板上，要改得重画底板」。真需要"擦"的只有一种情况：底板**残留了本该由图层替换的**字（那种字在参考图里有、在底板里也有但长得不一样，差值不为 0，probe 会量出来）——这时是请出图方重画底板，不是自己擦。实测有一次转换为此手写 `erase.ps1` + 三版试错，白烧十几分钟 |
| 参考图是 webp / jpg | 格式本身不用先转（`flat.cjs` 用系统 WIC 摊成 PNG，见 §1）。**但 jpg/webp 在字边缘有压缩噪声**，会把整片纸点亮点、行连成一坨：probe 底噪 >4% 时会打 ⚠ 并建议 `--T 45`（实测同一版面 PNG@T24 量到 322 块，jpg@T24 只有 6 块、T60 才 107 块）。**能要 PNG 就要 PNG**；已经量成一坨就加 `--T` 重跑一次，别手工去拆块 |
| 同一版式改了底板/重排，不想再读一遍字 | `probe` 带 `--from 上一版.html`（§2）：按锚点就近一对一搬 `text`+`font`+`weight`，坐标字号仍以这次量的为准。一层都没配上＝版式整体挪过或不是同一张图，这时才回去用 `--ocr` |
| PSD 打开报「因为发生错误导致无法读取此文档中的某些文字图层，所以已将这些文字图层栅格化」 | 文字层写的字体名 PS 解析不了：TiKi 只认 **PostScript 名**且必须是 ASCII，中文家族名（`思源黑体 CN`）会让整层被栅格化成死字。`psd.cjs` / 页面内那条路径都用 `psSafeFamily()`/`psFace()` 兜底（`SC.facePs` 里查得到就用真名，查不到就把非 ASCII 剔掉、退成 Arial），**并且 `build` 必须把稿件用到的每一族的 `facePs` 都内联进去**——只内联一族时换字体后页面里没有第二族的记录，PSD 里就写出中文名字 |
| 文字有重影/双份 | ①底板残留文字；②该家族没有目标字重被合成假粗 —— `fonts.cjs` 查字重，换家族或降字重 |
| 拖动文字很卡 | 拖动途中整篇 `render()` 了。当前引擎只在松手时提交并重排一次，`measureText` 还按「样式+文本」缓存 —— 自己改引擎时别再在 `pointermove` 里重排 |
| 认字体把整族认成另一族（宋体稿只认出华文中宋、隶书稿认成微软雅黑） | 十有八九是**候选池里根本没有真那一家**：前缀名把位子占满了。`fontid` 已让系统类名优先入席并点名补 思源/冬青/Noto；自己 `--pool` 时也别只给两三家 |
| 段落文本一填多行、认字体就报「没比字形」 | 每行切出的单字数与整段字数对不上，`fontid` 宁可不错配（已按行配对修好）；自己填段落时记得**按参考图的换行处写 `\n`** |
| 认字体认不出、或只给个"方向" | 三种情况：① `scene` 里还没有已知文字 —— 认字体要拿**同一个字**比形状，先把字填进 scene（§2）再跑；② 字号太小（≤30px，笔画只有 1~3 px）—— IoU 整体压到 0.3~0.45、名次会抖，它就不 `--apply`，只把候选缩到前三家交给 `fontpick` 比整页差值；③ 候选表里没有真字体（`--pool` 手动给、或 `--max` 调大）。判准了一律只比 3 家，绝不放回 3748 家全库 |
| 拆出来的三层字号大得离谱（55 被推成 153） | `--fit` 按 `blocks.json` 的 `fits` 认每层的墨迹宽；粘行那层的宽是**整行**的宽，除以菜名的字数就爆。`fill.cjs` 拆行时会把这层的宽改成菜名那段（`adv(菜名)×字号`）—— 自己写脚本补层就会重现这个坑，别自己写 |
| 一次转换里 agent 现写了 `fill_scene.cjs` / `fix_rows.cjs` / `clamp_sizes.cjs` | 那是 fill.cjs 已经包办的三件事（填清单、拆粘行、钳离群字号）。2026-09-28 查 WorkBuddy 实录：这一段 8 分钟、留了 7 个临时脚本。改用 `fill.cjs --dump`＋`--map` |
| 面板里选不到本机字体 | 老版用 `<datalist>`，Chrome 只按输入框当前值做前缀过滤，3700 个家族时等于什么都不显示。现在「字体」框本身就是搜索框，点它或框里的 ▾ 展开本机字体表；表空 = `build` 时没带 `--fonts auto` |
| 属性面板里字号/颜色看着是空的或 `undefined` | 面板要回填**实际生效值**（`styleOf()`），不能只读元素自己的字段，否则继承全局默认的那些字段全是 `undefined` |
| 引导点线/分隔线没画出来 | 线段缺 `x2` 也没有 `len`（`build` 会 WARN）；或 `width` 写成 0。点线的点距在 `dash` 里，`"0.1 15"` 表示每 15 设计像素一个点 |
| 点线比参考图密/疏 | 改线段 `dash` 的第二个数（点距），别改 `width`（那是点的大小） |
| 屏幕上点线是圆的、导出图是方的（或反之） | DOM 与 canvas 两套画法必须共用同一个 `lineOf()` 算出的 dash 数组，别只改一边 |
| 选中了按 Delete / 方向键没反应 | 焦点还留在右侧面板的输入框里 —— 快捷键要让位给打字（否则改数值时按退格会把图层删掉）。以前因此看起来像"删除失灵" | **Delete / Backspace 现在排在"焦点是否在框里"这道关卡之前判**：只认"有没有真在打字"（`FTYP`＝该框被 focus 后收到过 `input` 事件；代码回填数值不触发）。没敲过字＝焦点只是留在框里，照样删图层；在文字/数字框、内容框、就地改字里打过字＝删的是字，一个图层都不掉。另：单击图层 / 框选松手 / 快速选择 / 粘贴完都会 `defocus()` 把焦点交回画布 |
| 图层点不动、也框不进选择集 | 它被锁定了（数据里有 `lock:1`，图层带琥珀色虚线框和一个小锁牌） | 「解锁全部」或 `Shift+L` 放开全部；只想动其中一个就 Alt 单击它 |
| 「快速选择」的下弹不出来 / 对齐没按心里那个层走 | 浮层 `#qsx` 的 `z-index` 必须高于顶栏 `#top`（50），否则弹了也被工具条盖住；对齐基准是 `ORD[0]`＝**第一个选中的层**，而框选和快速选择是一次性命中、没有先后，所以退回按选区外接框 | 想钉住某个层当基准：先单击它，再 Shift 逐个加选（带品红虚框的那个就是基准）；状态行每次都会报基准是谁 |
| 框到图层一角却没选中 | 不是 bug：那一笔是**从右往左**拖的（从右往左＝整层被框进才选，从左往右＝碰到就选） | 从左往右重框一次；状态行会报本次用的是哪种口径 |
| 文字轮廓描边没出现 | `ow` 是 0 或没写（它是描边的开关）；或改了 `assets/stage.html` 却没重新 `build`（`set` 不换引擎） |
| 描边把字撑粗了、笔画糊在一起 | 有人把 `opos` 写成了 `center`（描边压在笔画正中）——**默认已经是 `outside`**（向外扩，不改字形），删掉这个字段或写 `"opos":"outside"` 就恢复；要只在笔画内部一圈才写 `"inside"` |
| 内侧描边看起来整字变了色 | 宽度超过笔画一半时内侧必然被填满，属正常 —— 调小 `ow` 或改用 `outside` |
| 属性刷把位置/文字也搬过去了 | 不会。三种复制都只刷样子（颜色/底色/描边/字体那套），位置、内容、类型、组合一律不动 |
| 整列字统一偏右下约 1/4 个字号 | 没开顶层 `"yink": true`。量到的都是墨迹，按 CSS 行盒/笔尖排就会统一偏 |
| 屏幕上看是对的，导出图每行低半格（或反过来） | DOM 与 canvas 两套排版算歪了。最常见是 span 的 `cssText` 里 `font:` 简写写在 `line-height:` 之后 —— 简写会把 line-height 打回 `normal`。简写必须在前 |
| 字形整体偏高/偏低半格 | 加 `dy`（正值往下），不要改 `y` |
| 段落折行位置与参考图不同 | 折行由 `w` 决定；参考图是手动的按行断句时，改成多个 point 元素或写 `\n`。默认避头尾是**严格**，中文标点不会出现在行首，看着就像"少排了半行"——想复刻参考图的硬断句把 `kin` 设成「无」 |
| 段落选中了却没有可拖的框 | 只有 `kind:"para"` 画框把手（`drawHandles()` 里判 `u.frame`）；点文本的把手是四角缩放，不吃 `w/h` | 面板把「类型」改成段落文本，或拖框右/下/右下角 |
| 拖段落的虚线边框却选走了一堆别的字 | 框是 `pointer-events:none` 的（否则点不到里面的字），所以边线上那一击原本会穿到底下的图层容器上，被"空白处拖＝框选"那条判定接走 → 变成橡皮筋。现在四条边上各贴一条透明边条（`#hnd i.eg`）来接住这一击，厚度按 `10/SCALE` 算，缩到 34% 也还有 10 屏幕像素 |
| 两端对齐没把行拉满 / 长数字串被压扁 | `justify` 只**拉伸**（`avail>lw` 才动字距），只放不收；末行、空行一律不拉 | 想让末行也齐就手动补空格或改回 `left`；要逐行精确就拆成多个 point |
| `rows.cjs` 报读不出/整片都是墨迹 | 它只解 PNG；透明文字层要先 `tojpg.ps1 -Background "#ffffff"` 压平。红底白字被误判时调 `--dark` |
| `probe.cjs` 量出来的字色是背景色、位置也怪 | 参考图和底板给反了。它自己会判并打印正确参数，看到"已自动把两张图对调"就别再手动换回去 |
| `probe.cjs` 只量到半张图 | 底板那半张**残留了文字**：两图相减没有差，就找不到字。这不是测量问题，得让出图方按同一尺寸重出一张真无字底板，或只交付能量到的那半张并说明限制 |
| `probe.cjs` 一个块都没量到 / 报"两张图几乎一样" | 底板根本没去掉字，或两张是同一张图。调 `--T`（默认 24）也不会变好，先确认输入 |
| 版面里几行字被并成一个 para | 它们行间距小于 `--gap`（默认 16）。调小 `--gap` 重跑，或在骨架里把那一块拆成几条 |
| 导出图与屏幕不一致 | 不可能（同一套排版数据）；若确实不同，多半是字体未加载完，`export.cjs` 已用 `--virtual-time-budget` 等待 |
| `psd.cjs` 报「缺少 ag-psd」 | `npm i ag-psd`（脚本会从稿件目录、当前目录、脚本目录逐级往上找 `node_modules/ag-psd`，最后试 `~/.qoder/ag-psd`；也可用 `AG_PSD_DIR` 直接指过去）。node_modules **不要**放进 skill 目录 |
| PSD 进 PS 弹「替换字体」、字形跟 HTML 对不上 | 两种原因：① 那台机器没装稿件用的字体；② **PSD 里写的是家族名而不是 PostScript 名**（PS 只认后者）。`build` 时带 `--fonts auto` 就会把稿件用到的那几个 PostScript 名存进数据块 `facePs`，两条 PSD 路径都读它；老交付件里没有 `facePs`，重新 `build` 一次即有 |
| PDF 里的文字在 Illustrator 里成了轮廓、改不了 | 那份稿子用的字体是 **CFF/OTF 或可变字体**（如思源黑体 CN），Chrome 打印只能写成 Type3；换成内嵌的 `@font-face` 子集也一样是 Type3 | 逐层改字改用「SVG（分层·活字）」；或把字体换成**静态 TrueType**（黑体 SimHei、微软雅黑…）再出 PDF。`build` 会警告，页面点「印刷 PDF」也会在状态行提醒（数据块里的 `cff`） |
| PSD 里文字颜色发黑、和页面上不一样 | ag-psd 两套颜色口径不同：文字样式 `fillColor` 吃 **0~255**，图层样式颜色吃 **0~1**。写反了不报错，只是颜色全变黑 |
| PSD 里段落换行和页面对不上、改框宽不回流 | 段落层必须送**原文**：把页面折好的行用 `\n` 拼起来送进 ag-psd，会被编成 `\r`＝硬回车，PS 就当它是很多段。另外给 `everyLineComposer:true`（页面是一行行贪心填满）；合成器与禁则不可能和 PS 一字不差，差几处属正常，别为此把折行再拼回去 |
| PSD 里段落文本还是点文本 / 组没变成图层编组 | 这份稿子是旧引擎出的，重新 `build` 一次（`set` 不换引擎）。段落要 `shapeType:"box"`＋`boxBounds:[0,0,框宽,框高]`＋`transform` 的 tx/ty＝**框左上角**（不是基线）；编组要 `children` 树，ag-psd 才会写 `sectionDivider` |
| 两端对齐进了 PSD 没生效 | ag-psd 的 `justification` 枚举**带连字符**（`'justify-left'`），写成 `'justifyLeft'` 它 `indexOf` 不到、把值编成 -1，不报错 |
| 段落实测"一行塞进两倍的字、右边冲出框外"，字还明显偏小 | 稿子的 `text` 块**没写 `weight`**（`probe` 出的骨架就不写）。`cssFont()` 会拼出 `font:undefined 34px "黑体"`：CSS 简写整条作废 → DOM 退回 16px；而给 `ctx.font` 赋非法串是**静默失败**，canvas 保留上一次的 `10px sans-serif`，于是量字按 10px 量、折行就按 10px 折。现在 `styleOf()`/`cssFont()` 都兜到 400 |
| PSD 里字看着比页面小三四倍 | 那个软件按 **72dpi** 解释 pt，而 PSD 里字号写成了按稿件分辨率换算的 pt（老版本坑）。**现在两版字号都直接写设计像素**，PS 排版时 1pt 当 1 像素用，不会再缩水；真出现就是拿了一份旧稿，重新 `build` + 重导。要在 Illustrator / Corel 那边也稳，用「SVG（分层·活字）」 |
| PSD 里线段拖不动端点、只能整层挪 | 那份导出时勾掉了「线段转形状图层」（或用了 `psd.cjs --lines bitmap`），线段就只是一层像素 | 保持勾选重导：线段会带 `vectorMask`＋`vectorStroke`，进 PS 是「直线工具」那种形状层，端点、粗细、颜色、虚线都能改 |
| PSD 的文字层在别的软件里是空的 | 活字层故意不带位图（322 层各存一张 4K 位图会撑爆文件），PS 打开自己重排；整版压平预览默认已经带在 PSD 里（`psd.cjs --no-preview` 才去掉），别的软件看那张 |
| SVG 打开后字是默认衬线体 | 稿件用的字体那台机器没装（SVG 只写字体名，不像 PSD 能带 PostScript 名映射）。换成本机装有的字体，或用面板里的字体选择器重挑 |
| SVG 里没有底板 | 这份稿子的 `scene.board` 是空的（只有 paper 底色）。SVG 的内联 `<image>` 直接取自数据块，数据块没有就画不出 |
| PowerShell 脚本报"字符串缺少终止符" | .ps1 必须是 UTF-8 **带 BOM**，本 skill 的文件已带；新建脚本时别丢 BOM |
| 16K 导出失败 | 画布超过 Chrome 限制，改用 `--layer text` 分层出图或降档 |
